# AI Match Lab — генератор видео «5 AI-моделей предсказывают счёт»

Матч (или готовый прогноз CoinPlay AI) → один прогнозный счёт → видео, где
простой распечатанный листок держат в руке на тематическом фоне и счёт
проявляется в боксе → zip-кит → Telegram-группа → автопостер
`coinplay-predictions-to-social` публикует в Threads, Instagram (Reels) и X.

```
fixtures.py / coinplay_sets.py / telegram_caption.py ──► матч + счёт
            │
            ▼
         poster.py ──► blank.jpg (листок с пустым боксом на фоне)
                   └─► filled.jpg (тот же листок, бокс заполнен)
            │
            ▼
         video.py ──► first+last frame ──► счёт проявляется в боксе
            │          (по умолчанию Veo 3.1 Lite через OpenRouter — тот же
            │           ключ, что и для прогнозов, без отдельного FAL_KEY;
            │           fal.ai/kling25/veo31 — запасные, более дорогие варианты)
            ▼
         ffmpeg: склейка + стоп-кадр 2 сек ──► video.mp4
            │
            ▼
         kit.zip (kit.json + threads/ instagram/ x/) ──► Telegram ──► автопостер
```

Вспомогательный модуль `config.py` разбирает переменные окружения: опечатка
(`HOLD_SEC=2,5`) больше не роняет прогон, а логируется и заменяется дефолтом.

## Реальная статистика в промпте

Перед запросом к моделям `stats.py` тянет бесплатные CSV с
[football-data.co.uk](https://www.football-data.co.uk) (без ключа, 22 европейские
лиги) и считает по ним:

- **Elo** обеих команд (свой расчёт по всей скачанной истории — CSV не даёт готового рейтинга);
- **форму** за последние 5 матчей (W/D/L, средние голы забитые/пропущенные);
- **личные встречи** (H2H) — сколько раз кто выигрывал, средняя результативность.

Эти цифры добавляются в промпт каждой модели строкой "Real stats: …", моделям
явно сказано ставить свежие новости (травмы, замена тренера) выше исторической
статистики, если они расходятся.

Лига определяется по полю `competition`: сравнение идёт по нормализованному
ключу (регистр, точки, дефисы и диакритика не важны), список — в
`stats.LEAGUE_CODES`. **Не работает** для сборных и турниров без клубного сезона
(Чемпионат мира, товарищеские, Лига чемпионов) и для эсенспорта/UFC — там просто
нет данных на football-data.co.uk, и генератор молча идёт дальше без блока статистики.

Имена клубов, которые в CSV пишутся иначе, чем обычно (`Man City`, `Man United`,
`Ath Madrid`, `Paris SG`), прописаны в `stats.ALIASES` — дополняй по мере
надобности. Если команда не найдена, в лог уходит подсказка с нормализованным
именем и примером того, как клубы называются в CSV.
`USE_STATS=false` — отключить совсем.

## Почему первый + последний кадр

Видео-модель, которой дали только пустой бланк, напишет **свои** цифры: не те,
что предсказали модели, и не те, что в подписи поста. Поэтому последний кадр
рендерится заранее с нашими цифрами, а модель только рисует между кадрами руку
с маркером. В конце ролика на бланке всегда правильный счёт.

## Запуск

```bash
pip install -r requirements.txt          # + ffmpeg в системе
export OPENROUTER_API_KEY=...  FAL_KEY=...
export TELEGRAM_BOT_TOKEN=...  TELEGRAM_CHAT_ID=-100...   # группа, которую читает автопостер

python generate.py --home Spain --away Argentina --home-flag es --away-flag ar \
    --competition "World Cup Final" --date 2026-07-19

python generate.py --match-file matches.json      # пачка матчей
python generate.py --auto                         # сам подберёт ближайшие матчи

# готовые прогнозы CoinPlay AI (sets.json) — без OpenRouter и без HLTV,
# фон подставляется по вертикали (football/esports/ufc)
export SETS_API_TOKEN=...
python generate.py --sets-vertical football
python generate.py --sets-vertical esports
python generate.py --sets-vertical ufc

# то же самое, но из текста поста "COINPLAY AI PREDICTIONS" (если нет
# SETS_API_TOKEN) — копия/вывод своего Telegram-скрейпера в файл
python generate.py --caption-file post.txt --caption-vertical football
```

Полезные флаги:
- `--no-video`: только кадры, промпт и кит с картинкой. Бесплатно, удобно проверить бланк.
- `--scores "1-2,2-1,2-2,1-0,2-1"`: свои счета без запросов к моделям (порядок ChatGPT, Claude, Gemini, Perplexity, Grok).
- `--no-send`: не отправлять в Telegram.
- `--keep-temp`: оставить промежуточные `_seg*.mp4` (по умолчанию удаляются).

Всё складывается в `out/<матч>/`: `blank.jpg`, `filled.jpg`, `prompt.txt`,
`predictions.json`, `video.mp4`, `<матч>.zip`.

Код возврата: `0` — все матчи собраны (или календарь пуст при `--auto`),
`1` — хотя бы один матч не собран. В конце прогона в лог уходит строка «Итог: …».


Тесты закрывают найденные баги регрессиями: порядок матчей в `stats`, разбор

## Провайдеры видео и цена ролика

`VIDEO_PROVIDER` выбирает, кто рендерит ролик. На листе всего один бокс
(счёт/победитель), поэтому видео — всегда ровно один сегмент на матч, цена
ниже не зависит от числа моделей/строк в прогнозе.

| Значение | API | Нужен ключ | Цена за ролик |
|---|---|---|---|
| `or-seedance-fast` (по умолчанию) | OpenRouter | `OPENROUTER_API_KEY` (тот же, что для прогнозов) | 4 сек × `$0.04`/сек ≈ **$0.16** |
| `or-veo31lite` | OpenRouter | `OPENROUTER_API_KEY` | `OR_VIDEO_DURATION` (по умолчанию 4) сек × `$0.03`/сек (720p, без звука) ≈ **$0.12** — дешевле всех, но на реальных роликах хуже всех держал текст: плыл уже на первом кадре, проценты расползались по экрану, а клетка со счётом однажды превратилась в сплошную заливку без цифры. Не рекомендуем, если не готовы мириться с браком |
| `or-seedance-mini` | OpenRouter | `OPENROUTER_API_KEY` | 4 сек × `$0.034`/сек ≈ **$0.13**, но модель меньше — может просесть качество |
| `kling25` | fal.ai | отдельный `FAL_KEY` | 10 сек ≈ **$0.70** — самый надёжный по опыту прошлых генераций, но заметно дороже |
| `veo31` | fal.ai | отдельный `FAL_KEY` | 8 сек × `$0.40`/сек (1080p, со звуком) ≈ **$3.2** |

Раньше, пока на листе была построчная таблица по моделям, ролик резался на
несколько сегментов (`SEGMENTS`/`PREFILL_ROWS`) — одна строка на сегмент,
иначе реальная генерация путала элементы между клетками (цифры наплывали на
гербы, подписи двоились). С переходом на один бокс со счётом (см.
«Оформление» ниже) резать стало нечего — `_segments`/`SEGMENTS`/
`PREFILL_ROWS` убраны вместе с мёртвым кодом, который их использовал.
Если `seedance-fast` не вытянет мелкий текст на реальной генерации —
следующий шаг попробовать `kling25` (дороже примерно в 4 раза, но именно
под него написаны все текущие анти-галлюцинационные формулировки промпта).

`or-*` идут через OpenRouter (openrouter.ai/docs/guides/overview/multimodal/video-generation)
— отдельный `FAL_KEY` для них не нужен, подходит уже существующий
`OPENROUTER_API_KEY`. `kling25`/`veo31` — через fal.ai, это отдельный сервис
и отдельный ключ (`FAL_KEY`); держим их как запасной вариант, если качество
`or-*` не устроит.

## Источник CoinPlay AI (`--sets-vertical`)

`--sets-vertical {football,esports,ufc}` — альтернатива `--auto`/`--match-file`
для трёх вертикалей, где прогнозы уже готовы: вместо того чтобы самим
опрашивать модели через OpenRouter (`predictions.py`) или собирать расписание
через football-data.org (`fixtures.py`), генератор забирает уже посчитанный
CoinPlay AI набор прогнозов и консенсус из `sets.json`
(`coinplay_sets.py`) и просто рисует постер поверх них — ни одного вызова
OpenRouter, ни парсинга HLTV.

Что нужно:
- `SETS_API_TOKEN` — токен для `Authorization: Bearer ...` (обязателен).
- `SETS_API_URL` — адрес экспорта, по умолчанию `https://209.38.103.35/sets.json`.

Под каждую вертикаль — свой фон (`assets/tables/{football,esports,ufc}.jpg`,
сгенерированы процедурно, см. `tools/render_table_themes.py`; любой из них
можно заменить своим файлом через `TABLE_IMAGE_FOOTBALL` /
`TABLE_IMAGE_ESPORTS` / `TABLE_IMAGE_UFC` — например реальным фото или
AI-генерацией, если позже подключите `OPENAI_API_KEY` и нужный скилл; код
менять не придётся, подложка подхватится по пути из переменной окружения).

У UFC в `sets.json` нет счёта (`score` всегда `null`, только победитель и
метод победы) — вместо выдуманного счёта в таблице показывается `1–0`/`0–1`
в пользу предсказанного победителя, а подписи к посту используют
формулировку «pick», а не счёт.

Дедуп по уже отрисованным матчам работает через тот же `state.py`
(`POSTED_STATE_FILE`), что и `--auto` — значит матч `coinplay-<match_id>`
не нарисуется дважды при регулярном запуске по cron/Railway.

**Важно:** схема `sets.json` реализована по текстовой спецификации от
владельца API — свериться с живым ответом сервера из песочницы, где это
собиралось, не удалось (сеть наружу туда заблокирована). Перед первым
реальным прогоном в проде стоит прогнать `--sets-vertical football` один раз
вручную и проверить, что видео и подписи получаются осмысленными; если в
реальном JSON какое-то поле называется иначе — поправить `coinplay_sets.py`
(там же, в docstring, это прямо оговорено).

## Сервис для грабера (`--serve`, дефолт Docker-образа)

Основной режим. Грабер (`coinplay-predictions-to-social`) уже читает группы
«approvals» и скачивает каждый zip-кит бота; увидев в архиве `blank/blank.json`,
он пересылает архив сюда. Генератор делает видео и кладёт готовый кит в группу
вертикали, откуда грабер публикует его в соцсети как обычно. Токена `sets.json`
и второго входа в Telegram не нужно.

```
группа «CoinPlay approvals» ──Telethon──► грабер ──POST /kit──► ai-match-lab (--serve)
        ▲                                   │                         │ kit_source → видео
        │                                   └─ картинки из кита       ▼
        └──────── группа вертикали ◄──────── кит с видео ◄── Telegram (TELEGRAM_CHAT_ID_<V>)
                       │
                  грабер публикует видео
```

`POST /kit?name=<имя>.zip`, заголовок `Authorization: Bearer <KIT_API_TOKEN>`,
тело — сам zip (до 25 МБ). Ответы: `202` принят и поставлен в очередь, `200`
этот `match_id` уже сделан/в работе, `401` неверный токен, `422` битый архив
или неподдержанный спорт (теннис и т.п.), `413` слишком большой. `GET /health`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `KIT_API_TOKEN` | — | **обязателен**: общий секрет с грабером (там `VIDEO_GENERATOR_TOKEN`); без него сервис не стартует |
| `PORT` | `8080` | порт приёмника (Railway задаёт сам) |
| `TELEGRAM_CHAT_ID_FOOTBALL` / `_ESPORTS` / `_UFC` | `TELEGRAM_CHAT_ID` | группа, куда уйдёт готовый кит этой вертикали; **её должен читать грабер** (`SOURCE_CHAT_ID`) |
| `WATCH_MAX_ATTEMPTS` | `2` | попыток на матч (каждая платная); дата в прошлом отклоняется сразу |
| `KIT_INBOX_DIR` | `<каталог state>/inbox` | куда временно кладутся принятые архивы |

- Видео делает один воркер по очереди; повтор того же матча игнорируется
  (`coinplay-kit-<match_id>` в `posted.json` — нужен Volume на `/app/state`).
- Cron Schedule у сервиса должен быть пустым — это постоянный сервис.
- Слушает IPv4 и IPv6, поэтому подходит приватный адрес Railway
  `http://<сервис>.railway.internal:<PORT>` (у грабера `VIDEO_GENERATOR_URL`).
- Видео-кит уходит в группу **без** `blank/`, поэтому грабер его обратно не
  пересылает — петли нет.
- Для публикации видео у грабера должен быть `VIDEO_KIT_ENABLED=true`.

## Запасной режим: опрос публичного канала (`--watch`)

`python generate.py --watch` — сервис, а не крон: раз в `WATCH_POLL_SEC`
секунд смотрит, не вышел ли в канале CoinPlay AI новый пост
«🤖 COINPLAY AI PREDICTIONS», и сразу делает по нему видео, потом шлёт кит в
Telegram-группу (дальше его забирает `coinplay-predictions-to-social`).
Это дефолтная команда в `Dockerfile`.

**Источник — публичное превью канала, токен не нужен.** У публичного канала
есть `https://t.me/s/<канал>` — последние ~20 постов обычным HTML. Пост
разбирает тот же `telegram_caption.py`, что и для `--caption-file`
(`channel_watch.py`). Bet Builder, опросы и результаты пропускаются.
Ограничение то же, что у `--caption-file`: в тексте поста только агрегат
панели (N из M, счёт, confidence, risk), построчного разбора по моделям нет —
он есть только на картинке поста.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `WATCH_VERTICALS` | `football,esports,ufc` | какие вертикали отслеживать |
| `TELEGRAM_CHAT_ID_FOOTBALL` / `_ESPORTS` / `_UFC` | `TELEGRAM_CHAT_ID` | своя группа для кита каждой вертикали; нет — общий `TELEGRAM_CHAT_ID` |
| `WATCH_CHANNELS` | football → `coinplayfootballai`, esports → `coinplayesportai`, ufc → `coinplayufcai` | свои каналы: `football:имя,esports:имя` |
| `WATCH_SOURCE` | `channel` | `sets` — брать из `sets.json` (нужен `SETS_API_TOKEN`) |
| `WATCH_POLL_SEC` | `60` | период опроса |
| `WATCH_PER_CYCLE` | `3` | максимум видео за один проход — защита бюджета |
| `WATCH_MAX_ATTEMPTS` | `2` | сколько раз пробовать упавший матч (каждая попытка платная) |
| `WATCH_BASELINE` | `true` | при первом старте не рисовать уже опубликованные посты |

- **Baseline.** При первом старте по вертикали все посты, уже видимые на
  превью, помечаются виденными (видео не делаются), дальше обрабатываются
  только новые. Маркер лежит рядом с `posted.json` на томе — перезапуск
  контейнера baseline повторно не снимает. Нужен Volume на `/app/state`,
  иначе после каждого деплоя baseline снимается заново и предикты, вышедшие
  за время простоя, пропускаются.
- **Группа на вертикаль.** Автопостер читает отдельные группы по вертикалям
  (футбол, UFC, …), поэтому для эсперта и UFC задай `TELEGRAM_CHAT_ID_ESPORTS` /
  `TELEGRAM_CHAT_ID_UFC`, иначе их киты уйдут в общую группу. Что куда уйдёт —
  видно в первых строках лога.
- **Cron Schedule у сервиса должен быть пустым**, иначе Railway будет
  останавливать процесс по расписанию.
- Недоступность источника (429, сеть) цикл не убивает — повтор через
  `WATCH_POLL_SEC`.
- Первая строка лога — сводка «предиктов сейчас видно N, разобрано M»: по ней
  сразу видно, что превью открылось и формат поста распознан. Если N=0 —
  канал не публичный или Telegram отдал другую разметку; если M<N — поменялся
  текст поста (правится в `telegram_caption.py`).
- Нужные для видео переменные (`OPENROUTER_API_KEY`, `VIDEO_PROVIDER`,
  `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, …) — те же, что и раньше.
  `FOOTBALL_DATA_API_KEY` и ключи моделей для `--watch` не нужны.

## Источник: zip-кит бота (`--kit`)

`python generate.py --kit furia-vs-auroragaming-1791297000.zip` — собрать
видео по готовому «social kit» бота CoinPlay AI, который он кладёт в группу
«CoinPlay approvals». Всё нужное уже лежит внутри (`kit_source.py`):

- `blank/blank.json` (schema 2) — команды, турнир, формат серии и 10 «лабораторий»
  с победителем и счётом каждой. Отсюда берутся строки моделей, консенсус
  («10 of 10 models agree»), главный счёт (самый частый среди проголосовавших
  за победителя — как «Most common score» в подписи бота) и вертикаль
  (`CS2` → esports, `UFC` → ufc, `Football` → football).
- Дата матча — из имени архива: суффикс `-1791297000` это unix-время старта (UTC).
- `instagram/caption.txt` — только «Average model confidence» для плашки.
- `blank/blank.png` и `blank/blank-prompt.txt` **не используются**: сцена
  генератора — лист в руке с одним боксом, цифры которого гарантируют первый и
  последний кадр. Видео-модели не доверяем вписывать 20 цифр рукой.

UFC без счёта: победитель кодируется как `1–0`/`0–1`, как и в `coinplay_sets.py`.
Повторно один и тот же кит не рисуется (ключ `coinplay-kit-<match_id>` в
`posted.json`).

## Источник: текст поста вместо sets.json (`--caption-file`)

Если `SETS_API_TOKEN` нет (например, токен выдавал не ты, а только текст
поста доступен через собственный Telegram-скрейпер) — `telegram_caption.py`
разбирает текст поста "COINPLAY AI PREDICTIONS" (football/ufc/esports)
напрямую, без обращения к `sets.json` вообще:

```bash
python generate.py --caption-file post.txt --caption-vertical football
```

`post.txt` — просто сохранённый текст поста как есть (один файл = один
матч). Из текста берутся: команды, лига, победитель/счёт по основному
прогнозу (или most common score — у esports формулировка другая, обе
понимает), N of M models agree, confidence, risk/danger.

**Важное ограничение**: построчная разбивка по каждой из 10 моделей (кто из
них как проголосовал) есть только в картинке-постере, которую бот публикует
рядом с текстом, — в самом тексте её нет, и мы её не распознаём (OCR не
делаем, слишком хрупко). Поэтому видео строится на агрегате: одна строка
"COINPLAY AI PANEL" с итоговым счётом/победителем, а N из M/confidence/risk —
в плашке AI CONSENSUS внизу карточки, а не 5-10 отдельных AI-логотипов, как в
`--sets-vertical`/`--auto`. Карточка от этого выглядит однострочной (под
таблицей остаётся пустое место, рассчитанное на больше строк) — рабочий, но
не окончательно отполированный вид; поправить можно отдельно, если понадобится.

## Автоматический подбор реальных матчей (`--auto`)

`Dockerfile` по умолчанию запускает `python generate.py --auto` — генератор сам
находит ближайшие реальные (ещё не сыгранные) матчи топ-лиг через бесплатный API
[football-data.org](https://www.football-data.org):

1. Зарегистрируйся (2 минуты, без карты): https://www.football-data.org/client/register
2. Добавь в переменные Railway: `FOOTBALL_DATA_API_KEY=<ключ из письма>`.
3. Готово — при каждом запуске берутся ближайшие по времени запланированные матчи
   из `FIXTURES_COMPETITIONS` в окне `FIXTURES_DAYS_AHEAD` дней.

Матчи со статусами `SCHEDULED` и `TIMED` считаются одинаково подходящими: у
football-data.org ближайшие игры почти всегда `TIMED`, и фильтр только по
`SCHEDULED` прятал как раз то, что нужно.

Если в окне вообще нет подходящих матчей (пауза в календаре, международное окно,
межсезонье) — это не ошибка: процесс тихо завершается с кодом 0 и предупреждением
в логе, а не падает. Так Railway не уходит в рестарт-луп.

В `FIXTURES_COMPETITIONS` по умолчанию — весь клубный список бесплатного тарифа
football-data.org (10 лиг). Особенно важна **BSA** (бразильская Серия A): у Южной
Америки своё, отдельное от УЕФА международное окно (CONMEBOL), которое почти
никогда не совпадает с европейским — когда все топ-лиги Европы разом встают на
паузу на 10+ дней (например, отборочные к Евро), Бразилейран обычно продолжает
играть, и `--auto` всё равно находит свежий матч.

`matches.json` + `--match-file` никуда не делись — это ручной/тестовый режим.

### Чтобы каждый день приходило новое видео

`--auto` при каждом запуске просто берёт САМЫЙ БЛИЖАЙШИЙ ещё не сыгранный матч.
Отсюда два момента, которые нужно настроить отдельно:

**1. Railway должен запускать контейнер РАЗ В ДЕНЬ, а не постоянно.**
`generate.py --auto` — это одноразовый скрипт (сходил, собрал видео, отправил,
завершился), а не вечный процесс. Обычный Railway-сервис после выхода из
контейнера либо перезапустит его сразу же (если Restart Policy = `Always` —
получится спам по несколько видео в день), либо будет пытаться и падать в
рестарт-луп. Правильный способ — **Railway Cron Schedule**:
1. Открой сервис -> **Settings -> Cron Schedule**.
2. Впиши, например, `0 9 * * *` (каждый день в 09:00 **UTC** — переведи на своё
   время, Railway крон работает в UTC).
3. Railway сам запустит контейнер по расписанию, дождётся выхода (`sys.exit`)
   и не будет перезапускать его до следующего срабатывания.

**2. Дедупликация — чтобы не прислать один и тот же матч два дня подряд.**
Если ближайший найденный матч ещё не сыгран к следующему крону (например, до
него было 3 дня), без доп. защиты `--auto` нашёл бы ЕГО ЖЕ и на следующий
день. Поэтому теперь после каждой успешной отправки матч запоминается в
`state.py` (файл `POSTED_STATE_FILE`, по умолчанию `state/posted.json`) и
больше не выбирается, пока не истечёт 60 дней. Чтобы это переживало между
отдельными крон-запусками (а не сбрасывалось при каждом старте контейнера),
**нужен Railway Volume**:
1. Сервис -> **Settings -> Volumes -> New Volume**.
2. Mount path: `/app/state`.
3. Готово — файл дедупликации теперь на постоянном диске, а не в эфемерном
   контейнере.

Без тома всё равно будет работать, просто дедупликация обнулится при
следующем деплое (переменные окружения при этом не теряются — теряется
только сам файл `posted.json`). Отключить дедупликацию полностью:
`FIXTURES_SKIP_POSTED=false`.

### Почему постоянно одна и та же лига

Дедупликация выше не даёт прислать ОДИН И ТОТ ЖЕ матч дважды — но не мешает
каждый день присылать матч из ОДНОЙ И ТОЙ ЖЕ лиги, просто разный. Причина:
`--auto` берёт самый ближайший по времени матч среди ВСЕХ лиг разом, а у
лиги с плотным календарём (например, Série A Бразилии — там игры почти
каждый день) на любой момент банально больше кандидатов на роль «самый
ближайший», чем у лиги, которая играет раз в выходные. Со временем это
статистически всегда перетягивает выбор на себя.

Начиная с этой версии `fixtures.fetch()` при выборе исключает турниры из
последних `FIXTURES_AVOID_LAST_COMPETITIONS` публикаций (по умолчанию `2`),
если это оставляет хоть какую-то альтернативу — то есть не блокирует
публикацию, если сейчас реально играет только одна лига. Ротация читает
историю турниров из того же `POSTED_STATE_FILE`, так что тоже требует тома,
как и обычная дедупликация. `FIXTURES_AVOID_LAST_COMPETITIONS=0` возвращает
старое поведение (просто самый ближайший матч).

## Дата матча

Дата обязательно должна быть в будущем (`YYYY-MM-DD`). Прошедшая дата означает,
что у матча уже есть реальный результат — модели этого не знают и просто
нафантазируют правдоподобный «прогноз», поэтому такой матч **отклоняется ещё до
похода к API моделей** (деньги не тратятся).
Отключить проверку: `ALLOW_PAST_DATES=true`.

## Фон

Лист занимает 72% ширины кадра (`poster.compose_frame`), остальное —
подложка (фон за рукой). Размер — **1080×1920**, лишнее обрезается по
центру. Два способа получить подложку — статичный файл на вертикаль или
AI-фон под конкретный матч (флаги/цвета команд) — подробно описаны в разделе
«Оформление» ниже и в таблице переменных (`TABLE_IMAGE_<VERTICAL>`,
`AI_BACKGROUND`). Если файла нет или путь битый — рисуется процедурное
дерево (`poster._procedural_wood`), прогон не падает.

## Как сделать ближе к референсу

1. **Иконки моделей** — используются в полоске «MODELS CONSULTED» (см.
   «Оформление» ниже), когда в прогнозе больше одной строки. `assets/icons/
   chatgpt.png`, `claude.png`, `gemini.png`, `perplexity.png`, `grok.png`
   (PNG с прозрачностью). Если файла нет, рисуется нейтральный значок.
2. **Эмблемы клубов** для клубных матчей: `assets/crests/<club>.png` или URL в
   `home_flag` / `away_flag`. Флаги стран подтягиваются сами по ISO-коду (`es`, `ar`, `gb-eng`).
3. **Длина.** Один сегмент (`OR_VIDEO_DURATION=4` по умолчанию) + `HOLD_SEC=2`
   стоп-кадр в конце — ≈6 сек. Длиннее — поднимай `OR_VIDEO_DURATION`
   (`or-seedance-*`: любое целое 4–15) или `HOLD_SEC`.
4. **Музыка.** Один трек на все ролики — `MUSIC_FILE=assets/beat.mp3`.
   Несколько (чтобы ролики не звучали клонами друг друга) — положи их в
   папку и укажи `MUSIC_DIR=assets/music`: на каждый матч автоматически
   берётся один из треков этой папки. Громкость — `MUSIC_VOLUME`
   (по умолчанию `0.25`), сдвиг по треку — `MUSIC_OFFSET` (сек, по
   умолчанию `0`) — чтобы подвести пик/дроп трека ровно под момент
   раскрытия вердикта (начало стоп-кадра). Трек зацикливается под всю
   длину ролика автоматически.

   Про «трендовую музыку по API» — специально НЕ сделано: у трендовых
   звуков TikTok/Reels/Shorts нет публичного API для скачивания и
   переиспользования вне самой площадки (лицензия только на показ внутри
   неё), а бесплатные библиотеки музыки (Jamendo и похожие) по их же
   условиям — только для НЕкоммерческого использования, промо-ролик
   казино под это не подходит. Легальный путь — один раз купить/получить
   небольшую библиотеку треков с коммерческой лицензией и положить их в
   `MUSIC_DIR`.
5. **Стоп-кадр в конце.** Не просто пауза — лёгкий наезд камеры (Ken
   Burns, `HOLD_SEC` секунд) и короткий синтетический «дзынь» ровно в
   момент перехода в стоп-кадр (оба эффекта генерируются локально,
   без дополнительных платных запросов к видео-API).

## Оформление (простой распечатанный листок)

Прогноз показывается на **простом белом печатном листке** — ровно как на
референсе: лого, команды, один бокс со счётом, призыв «LINK IN BIO». Никакого
AI-устройства/экрана/неона — это сознательный откат от более сложной
«AI-терминал» версии, которая была раньше (см. git-историю): референс
просил именно печатный листок в руке на фоне арены/стадиона, не гаджет.

`poster.py`:
- `render_paper()` рисует сам листок (`PAPER_W × PAPER_H` = 1680×1750, белая
  бумага `SHEET_BG`, чёрные чернила `SHEET_INK`) — лого-значок по вертикали
  (мяч/контроллер/перчатка, line-art, без брендов), команды с эмблемами,
  **один** главный бокс с итоговым счётом/победителем, под боксом — строка
  согласия моделей (`N OF M MODELS AGREE · RISK`), снизу `EXACT SCORE
  ALREADY POSTED` / `LINK IN BIO`.
- **Главный бокс — консенсус, а не ответ первой модели.** Значение берётся из
  `Match.hero_home`/`hero_away` (`generate._hero_score()`): если прогноз
  готов и уже агрегирован (`coinplay_sets.py`, `telegram_caption.py` — одна
  строка) — это она и есть; если прогноз живой и моделей несколько
  (`predictions.py`, `--scores`) — это САМЫЙ ЧАСТЫЙ счёт среди них (тот же
  расчёт, что и в подписи поста), а не случайно первая по списку модель.
  Для UFC счёта как такового нет (см. `coinplay_sets.rows_from_predictions`
  — победитель кодируется как 1/0), поэтому бокс показывает ИМЯ победителя,
  а не «1–0»; подпись над боксом меняется с `PREDICTED SCORE` на
  `PREDICTED WINNER` соответственно.
- **Полоска «MODELS CONSULTED»** — когда есть реальная разбивка по моделям
  (`Match.rows` длиннее одной строки — живой опрос или `coinplay_sets.py` с
  несколькими AI-лабами), под главным боксом рисуется до 5 иконок с
  индивидуальным пиком каждой модели (`+N` чипом, если моделей больше) —
  играем на том, что за консенсусом стоит несколько независимых ИИ, а не
  прячем это за одним агрегированным числом. Если прогноз и так всего одна
  агрегатная строка (`telegram_caption.py`) — полоски нет, и канвас листа
  короче на `STRIP_EXTRA_H` (`PAPER_H` — базовая высота без неё).
- `compose_frame()` кладёт готовый листок на тематический фон (`TABLE_IMAGE_
  <VERTICAL>` или AI-фон под матч, см. ниже) с лёгкой перспективой,
  светотенью сцены, зерном и тенью.

Два кадра на матч: `blank` (бокс пуст) → `filled` (бокс с нашим счётом/
победителем); видео-модель интерполирует между ними — что именно происходит
в кадре, описывает `video.build_prompt()`: одна рука держит лист неподвижно,
содержимое бокса просто проявляется, ничего больше в кадре не меняется
(полоска моделей статична в обоих кадрах — см. комментарий в
`poster._model_strip`).

**Фон (рука + стадион/арена/октагон)** можно брать двумя способами:

1. **Статичный файл на вертикаль** — `assets/tables/<vertical>.jpg` (или
   `TABLE_IMAGE_<VERTICAL>`), один и тот же для всех матчей этой вертикали.
   Без флагов/цветов конкретных команд. Сгенерировать свой набор —
   `python tools/generate_backgrounds.py` (нужен `OPENAI_API_KEY`).
2. **AI-фон под конкретный матч** (`backgrounds.py`) — цвета/флаги/баннеры
   команд этого матча на трибунах/в арене/на углах октагона, как на
   референсе («Бельгия → бельгийские флаги на трибунах»). Включается
   переменной `AI_BACKGROUND=1` (по умолчанию выключено — это платный вызов
   OpenAI (`gpt-image-1`) на каждый новый матч). Результат кешируется в
   `out/<slug>/_bg.jpg`, повторный прогон того же матча фон не
   перегенерирует (если не передать `--fresh-background`). На конкретном
   прогоне можно отключить флагом `--no-ai-background`, даже если
   `AI_BACKGROUND=1` стоит глобально (для бесплатных тестов через
   `--no-video`/`--caption-file`).

Если `AI_BACKGROUND` выключен, нет ключа или генерация не удалась (сеть,
safety-блок) — тихо используется статичный `TABLE_IMAGE_<VERTICAL>` (способ
1), прогон не падает.

- **Шрифт**: Roboto Condensed (Bold — заголовок, SemiBold — подписи), цифры
  в боксе и имя победителя в UFC — рукописный `Kalam-Bold`, чёрным по белому.
- Код прежней «AI-устройство»-версии (тёмный корпус, построчная таблица,
  неоновые цифры, маркер) удалён из `poster.py`/`video.py`/`generate.py`
  целиком, а не оставлен мёртвым весом — см. git-историю, если понадобится
  восстановить референс для сравнения.

## Куда уходит видео

- `VIDEO_PLATFORMS` (по умолчанию `instagram`) — площадки, в которые кит кладёт рилс.
  Threads и X по умолчанию без видео. Картиночный кит (видео не получилось) идёт на все три.
- Чтобы видео шло ещё и в YouTube Shorts: `VIDEO_PLATFORMS=instagram,youtube`
  (публикует грабер, ему нужны `YOUTUBE_*` — см. его README). В кит попадёт
  `youtube/post.txt`: первая строка — название, остальное — описание.
- `HOLD_STINGER` (по умолчанию `false`) — звуковой акцент «дзынь» в начале финального стоп-кадра
  (на 4-й секунде). Выключен: в хвосте остаётся только фоновая музыка.
- `TELEGRAM_SEND_PREVIEW` (по умолчанию `false`) — слать ли в группу отдельное превью-видео.
  Грабер публикует его отдельным рилсом (у превью нет манифеста, дедуп не срабатывает),
  поэтому включайте только для ручных тестов.

## Подпись поста

Генерируется из прогнозов: счета всех ответивших моделей, консенсус, самый частый
счёт и призыв «Link in bio». Для X своя версия, гарантированно до 280 символов.

## Деплой (Railway)

`Dockerfile` ставит ffmpeg и cairo, запускает контейнер от непривилегированного
пользователя и не буферизует логи. Сервис работает как cron-job
(`python generate.py --auto`).

## Что было исправлено

**Критично — статистика считалась неправильно**

- `stats._load_matches` разворачивал список дважды (`matches.reverse()` +
  `return list(reversed(matches))`), то есть не делал ничего, и матчи вообще
  никогда не сортировались по дате — сезоны просто склеивались подряд. В итоге
  «форма за последние 5 матчей» брала **первые** матчи сезона, а Elo считался в
  обратном хронологическом порядке (в `_compute_elo` вдобавок висел пустой цикл
  `for m in reversed(matches): pass`). Все три показателя в промпте были
  мусором. Теперь матчи парсятся с датой и сортируются от новых к старым, Elo
  идёт строго вперёд по времени и стал игрой с нулевой суммой.
- `Atlético Madrid` был прописан в алиасах как `Ata. Madrid`, а в CSV он
  `Ath Madrid` — статистика по Атлетико не находилась никогда.
- CSV декодировался как UTF-8, хотя football-data.co.uk отдаёт cp1252: команды с
  диакритикой приходили битыми и не находились. Добавлен перебор кодировок.
- Пустой ответ сервера клался в кэш и залипал там на 12 часов.

**Матчи не находились**

- `fixtures.fetch` запрашивал только `status=SCHEDULED`, а ближайшие матчи у
  football-data.org почти всегда `TIMED` — `--auto` регулярно «не находил
  матчей» при полном календаре. Теперь берутся оба статуса, добавлены дедуп,
  отсечка слишком близких по времени матчей и понятные ошибки на 401/403/429.

**Падения на ровном месте**

- Отказ одной модели ронял весь матч: `list(ex.map(...))` пробрасывал исключение
  наружу. Слоты стали независимыми, есть `MIN_MODELS`.
- `resolve_models` падал с `TypeError`, если у модели в каталоге `created: null`.
- `_parse` брал первую пару `{}` в ответе — при рассуждении с примером JSON
  парсился пример, а не ответ. Теперь ищется последний сбалансированный объект.
- `PROMPT.format(**match)` ломался на лишних ключах матча (`home_flag`,
  `kickoff_utc`). Передаются только нужные поля.
- Любая осечка при загрузке флага (CDN недоступен, битый файл) валила матч
  целиком — теперь подставляется заглушка с названием команды.
- Нечисловое значение в `SEGMENTS`/`HOLD_SEC`/`FIXTURES_*` роняло процесс до
  первого запроса. Разбор вынесен в `config.py` с логом и дефолтом.
- `os.environ['OPENROUTER_API_KEY']` / `['FAL_KEY']` давали голый `KeyError` —
  заменены на понятные сообщения с подсказкой.
- Отсутствие ffmpeg обнаруживалось только на этапе склейки, уже после оплаченных
  запросов к моделям и fal. Проверка перенесена в начало.
- Ошибки ffmpeg терялись: `check=True` без перехвата stderr. Теперь текст ошибки
  попадает в исключение.

**Данные и артефакты**

- Слаг для нелатинских названий получался пустым: `out_dir` совпадал с корнем
  `out/`, архив назывался `.zip`, следующий матч затирал предыдущий.
- `predictions.json` и `.zip` писались на месте — автопостер мог подхватить
  недописанный архив. Запись стала атомарной (`.tmp` + `os.replace`).
- Промежуточные `_seg*.mp4` никогда не удалялись и копились в `out/`.
- Падение отправки превью в Telegram отменяло отправку самого кита.
- Подпись поста жёстко печатала «/5» независимо от числа ответивших моделей;
  версия для X могла превысить 280 символов.

**Мелочи качества**

- Кадры сегментов рендерились с общим `random.Random(seed)`, состояние которого
  зависело от числа уже нарисованных цифр — на стыке сегментов цифры чуть
  «прыгали». Теперь seed привязан к координате строки.

- Шрифты пересоздавались в цикле подбора кегля — добавлен `lru_cache`.
- Деление на ноль в `_procedural_wood` на однородной текстуре, падение на пустом
  списке строк, битый `TABLE_IMAGE` — закрыты.
- `Dockerfile`: `PYTHONUNBUFFERED=1` (логи Railway больше не теряются при
  падении), непривилегированный пользователь, `.dockerignore`.
